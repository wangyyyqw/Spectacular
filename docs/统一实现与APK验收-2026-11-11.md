## 灰屏原因与修复

真机原始日志确认这是 Flutter Release 错误页。打开《方舟【多看版】》并翻页后出现：

```text
Bad state: 章节尚未准备，请先等待章节准备任务完成
ChapterStructureStore.prepared
ChapterPositions._coordinatesFor
ChapterPositions.readingPercentForCfi
EpubChapterSource.readingPercentForCfi
ReaderSession.readingPercent / progress / _progressToPersist
```

页面缓存与原文结构、位置缓存分别管理。辅助定位请求可能替换前台保护键，视口变化会清理坐标，预加载页面也可能对应已淘汰的原文结构。同步读取百分比因此抛出异常，并影响界面构建及进度保存。

修复位置：

- [chapter_structure.dart](../packages/reader_core/lib/epub/chapter/chapter_structure.dart)：实际可见章与最近前台准备分别保护，三章缓存容量保持；增加只读准备结果查询，冷缓存不触发同步解析。
- [epub_chapter_source.dart](../packages/reader_core/lib/epub/epub_chapter_source.dart)：当前阅读章同时固定结构与完成布局。
- [chapter_positions.dart](../packages/reader_core/lib/epub/chapter/chapter_positions.dart)：百分比在索引尚未准备时返回 `null`。必须已经准备的原文定位接口继续明确报错。
- [reader_session.dart](../packages/reader_ui/lib/reader_session.dart)：不缓存准备中的空百分比，重排提交后重新计算；跨章翻页、滚动和跳转检查目标 CFI，位置缺失时等待可取消的原文准备任务，已有位置或无正文进度能力时不重复请求。

## APK 构建与安装

使用本地 Flutter／Dart、Android SDK 和 Android Studio JBR。Dart 依赖复用缓存，Gradle 使用 `--offline`；本轮没有下载构建依赖。

所有 Flutter 测试结束后，在应用目录生成构建配置，并通过本地 Flutter Tools 的正式 `injectPlugins` 入口刷新 Release 插件注册：

```bash
cd apps/reader_mobile
flutter build apk --release --no-pub --config-only --target-platform=android-arm64

dart --packages=/Users/aaa/development/flutter/packages/flutter_tools/.dart_tool/package_config.json \
  dist/unified-final-evidence-20261111/generate_release_plugins.dart

cd android
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' \
  ./gradlew --offline --console=plain :app:assembleRelease \
  -Ptarget-platform=android-arm64 -Ptarget=lib/main.dart \
  -Pbase-application-name=android.app.Application \
  -Pdart-obfuscation=false -Ptrack-widget-creation=false -Ptree-shake-icons=true
```

注册脚本调用 `injectPlugins(FlutterProject.current(), releaseMode: true, androidPlatform: true)`，使用 Flutter 的模板渲染器；没有手改生成注册文件或删除测试依赖。构建成功耗时 **28 秒**。

## 未处理风险与下一步

1. **图文混合章的首页图片锚点是既有定位限制。** 《方舟》部分首页先显示装饰图片。正文存在时，`ChapterTextCoordinates.ratioFor` 只接受字符坐标，图片 CFI 暂不可定位；界面回退到章节估算，存储保留上一有效正文位置。序幕首页退出时触发过一次 `无法保存阅读位置的内容锚点，请重试`。该非空正文分支与本轮修改前的 HEAD 逐字相同，已单独记录，没有纳入灰屏修复，也没有宣称该首页续读通过。
2. 真机验证覆盖当前一本书、覆盖翻页、目录、边距、正文恢复和统计；未完成整书逐页、连续滚动及全部翻页模式、横屏、iOS／macOS 或其他机型的完整矩阵。商店签名与发布材料仍未准备。
3. 本轮最终验证按改动职责执行，保留条件跳过及真机入口自动映射边界，不把专项通过写成最终三包全量通过。

下一步建议独立补齐图文混合章中真实图片元素的正文位置映射，并用首页退出重开回归核验；持续沿用按改动选择测试与同一提交更新预期的规则。
