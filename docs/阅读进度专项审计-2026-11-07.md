# 阅读进度专项审计（2026-11-07）

本轮审计覆盖保存与恢复、后台与进程重启、翻页模式切换、字号与尺寸重排、目录与进度滑杆、百分比显示、内容版本与旧存储迁移。代码基线为 `6bb6703`。本轮只形成审计记录，没有修改业务实现。

结论：确认 **8 项缺陷（2 项 P1、6 项 P2）**，另有 **2 项定位精度或功能限制**。普通分页模式之间切换、正常后台刷新及一次真机后台后强制停止重开通过；不能据此认定所有退出和重排场景安全。

## 一、审计口径

- **正文位置**：以 CFI 和当前可见行判断；同一正文在不同字号下页码改变是正常现象。
- **视口位置**：连续滚动还需保留页内偏移；CFI 相同但滚动位置向前吸附到行顶，属于精度变化。
- **百分比**：应由正文字符位置推导，不能把书架、阅读页和存储的不同算法当成同一个进度。
- **已读完**：单独检查，不把模式恢复造成的程序滚动当成用户回翻。
- **证据等级**：下文区分源码与本地 Flutter 复现、手机现装包实测、尚未覆盖的设备条件。

### RP-01：重排没有保留连续操作之前的阅读锚点

`_drainOverrides()` 每轮从当前页重新取 `_anchorOf(currentPage)`，尺寸变化也采用分页锚点。重排只恢复到“包含锚点的页面”，下次操作又取这个新页面的较早锚点，回退可以累积。连续滚动时没有采用 `currentCfi` 所指的视口行，且 `_reloadChapter()` 一开始便清掉滚动偏移。

使用含 100 行、每行可定位 CFI 的单章源复现，行号均为样本中的零基编号：

| 操作 | 原位置 | 结果 |
|---|---|---|
| 分页模式反复调整字号 `16→20→16→20→16` | `line24 / CFI:158` | 每次锚点依次变为 `line20→line12→line10→line0`，最终 `CFI:0` |
| 滚动模式字号 `16→20` | `page2 / offset96 / line28 / CFI:186` | `line20 / CFI:130 / offset=null` |
| 滚动模式尺寸 `280×300→250×280` | 同上 | `line22 / CFI:144 / offset=null` |

字号和尺寸已实测；字体、行高、段距、边距走相同重排入口，存在同类风险，但本轮没有逐项组合实测。分页调整一次后原文仍在当前页中，并不等于反复调整后保持原文位置。

修复验收应保持一次设置交互中的原始正文锚点；调整后页码可以变化，反复返回原设置不能把正文越推越早。

### RP-02：滚动视图反写重排前的页号

`didUpdateWidget()` 发现会话 generation 变化就加载滚动窗口；此时 `session.loading` 仍为 true，读取的是旧 `progress`。新分页完成后没有再次改变 generation，旧窗口恢复任务继续按旧页码定位，最后捕获可见页并提交给会话。

完整 `ReaderPage` 的实测顺序：

```text
调整前：       page3 / offset268 / line56 / CFI382
开始重排：     page3 / offset=null / line45 / CFI305
会话重排完成： page5 / offset=null / line45 / CFI305
再等待200ms：  page3 / offset0   / line27 / CFI179
```

RP-01 与 RP-02 需分别处理：即使会话采用正确视口锚点，滚动视图仍可能把正确结果覆盖掉。验收需覆盖重排完成后的延迟提交，不能只在 `applyOverrides()` 返回时断言。

### RP-03：书尾恢复会自动改写阅读位置

恢复时把目标位置限制到 `maxScrollExtent`。书尾剩余内容不足视口高度，目标页无法放到顶部；恢复结束后 `_captureVisiblePage()` 将较早的首行当作新的阅读位置并保存。

实测均没有用户正文手势：

| 场景 | 保存或切换前 | 200ms 后会话 | 最终存储 |
|---|---|---|---|
| 分页末页切滚动 | `page7 / line98 / CFI676 / finished=true` | `page5 / offset350 / line83 / CFI571 / finished=false` | 显式 flush 后保存为 page5，读完标记为 false |
| 书尾连续滚动冷开 | `page7 / offset24 / CFI676 / finished=true` | `page5 / offset350 / CFI571 / finished=true` | 2300ms 后 page7 被 page5 覆盖 |
| 不足一屏的滚动位置冷开 | `page0 / offset96 / line4 / CFI24` | `page0 / offset0 / line0 / CFI0` | 2300ms 后 offset96 被 offset0 覆盖 |

冷开时已有 `_restoredFinished=true` 会保留读完标记；本次会话刚到末页再切模式则可能取消标记，两种情况不能混为一谈。短内容的保存种子用于验证不同视口恢复路径，未在手机上制造该条件。

### RP-04：只刷新会话无法补回滚动容器中待提交的位置

连续滚动的可见位置延迟 120ms 交给 `ReaderSession`。正常切模式、外部模式更新和 `ReaderPage.dispose()` 没有先调用 `flushVisiblePosition()`，滚动组件销毁后又取消该定时器。此时宿主或会话再调用 `flushProgress()`，读到的仍是旧位置。

完整组件复现：

- 滚动到 700px，1ms 后切 `cover`，会话仍是 page0。
- 滚动到 1400px，1ms 后销毁 `ReaderPage`，等待 200ms，存储仍是 page0。

这是直接覆盖组件更新和路由销毁边界的本地复现。经菜单切模式通常先消耗部分动画时间，本轮没有宣称每次真实点击菜单都能落入 120ms 窗口。后台生命周期回调已调用 `flushVisiblePosition()`，正常后台路径不等同于普通返回书架。

### RP-05：保存延期没有上限

`open()` 总把当前进度记为 `_lastPersisted`，因此 `_persist()` 中 `_lastPersisted == null` 的“首次变化立即保存”分支通常不触发。每次翻页或滚动提交都取消原定时器并从头等待 2 秒。

为缩短验证时间，设置 `persistInterval=100ms`，每 50ms 翻一页，持续 600ms 到第 12 页：**写入次数为 0，存储为 null**；停止操作再等 100ms 才有 1 次写入。默认 2 秒具有相同语义，丢失窗口不受 2 秒约束。

`inactive/hidden/paused/detached` 的正常刷新能补救；本缺陷的风险条件是未收到通知、通知尚未完成或应用异常终止。一次正常后台后强制停止通过，不能排除此问题。

### RP-06：正文位置没变也会显示不同百分比

单章真实 EPUB，CFI 落在章内字符总数的 50%，读取同一 `DriftProgressStore`：

```text
数据库 percent：50.0
书架：          在读 0%
阅读菜单：      62.5%（零基第4页，共8页）
```

原因：

1. 存储按内容锚点和字符权重计算。
2. 书架调用 `percentInt(current.spineIndex)`，没有传章内字符偏移；统计页同样如此，已读完时另强制显示 100%。
3. 阅读菜单和页家具采用 `(spine + (page+1)/chapterPages)/chapterCount`，对章节等权且受分页影响。

因此退出到书架、调整字号或切换显示界面会出现百分比变化，不一定代表保存丢失，但会掩盖实际位置问题。与[技术方案 §76](../方案/技术方案.md#76-进度与目录跳转实现规格)的字符比例口径不一致。

### RP-07：子目录误跳章首

`TocEntry` 已有 CFI 和 fragment，目录选择回调只调用 `jumpToChapter(entry.spineIndex)`。用同一 XHTML 中后半节目录复现：其 CFI 可通过 `jumpToCfi()` 正确定位 page2；点击该目录后却变为 page0。

现有目录测试只检查章节编号，无法发现同一章内的目录跳转错误。真正跨章的目录导航和书签 CFI 跳转现有测试通过。

### RP-08：旧进度迁移不能从部分成功状态继续

`migrateLegacyJson()` 逐条写入，但只要进度表非空就整体跳过。JSON 含甲、乙两书，模拟迁移中断后表中只有甲书：再次迁移返回 0，乙书 `load=null`。

影响旧版存储迁移中断或数据库已有部分进度的情况，不影响正常 Drift 保存本身。应按书处理已迁移记录，或保证整体迁移原子完成。
