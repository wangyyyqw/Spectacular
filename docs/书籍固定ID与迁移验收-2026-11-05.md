# 书籍固定 ID 与迁移验收

## 固定算法契约

对外 `BookEntry.id` 和数据库 `books.uuid` 统一使用 32 个小写十六进制字符。
规则由 `packages/reader_core/lib/epub/book_identity.dart` 中的
`generateBookId` 定义，跨设备调用同一算法即可获得相同标识。

1. 读取 EPUB 原始书名、作者和 OPF `unique-identifier` 指定的标识，通常为 UUID。
2. 三个字段分别去除首尾空白，缺失固定为空字符串；保留大小写、内部空白和标点。
3. 按固定顺序编码紧凑 JSON 数组：`["spectacular-book-id-v1",书名,作者,标识]`。
4. 将 JSON 编码为 UTF-8，计算 SHA-256，取前 128 位并输出 32 位小写十六进制。

不使用文件名、导入时间或随机数。修改书架展示书名、作者不会重新计算 ID。
合法 `fallback.opf` 仍读取原标识；无 OPF 的兼容文档使用空标识，不能将解析器
占位标识算入书籍身份。原始 EPUB 标识另存 `epubIdentifier`，字体解混淆仍使用
原 EPUB 标识，不能改用 bookId。

固定向量：`史记`、`司马迁`、`urn:uuid:12345678-1234-1234-1234-123456789abc`
生成 `5254e823ce6321371c8300ab4822eea2`；三字段全空生成
`098fb7fb98035c2deda40fd5c2c11163`。固定向量已由独立 Python 程序复算。

相同三元组视为同一本书；任一字段变化视为另一身份。该契约适合后续备份和同步
关联键，本次未实现备份或同步。128 位摘要不能保证数学上的绝对无碰撞；缺失 UUID
时，同名同作者书籍会按当前规则视为同一本。算法版本以后只能新增，不能静默改写。

## 存储、查重与旧库迁移

- 数据库升级至 schema 13，新增原标识、算法版本和旧 ID 别名。内部整数主键不变。
- 启动在旧 JSON 书库迁移后、孤儿扫描前迁移 ID；导入前也执行同一入口。
- 迁移从原 EPUB 获取身份，事务更新 `books.uuid`、分组与标签的字符串关联。
  原书路径、用户编辑的资料和整数外键数据保持原样，旧进度 JSON 可以按旧别名解析。
- 新书存入 `files/books-v1/<bookId>/source.epub`；旧书保持原目录。两个命名空间隔离，
  避免旧 ID 恰好等于新摘要时覆盖别的原书；孤儿扫描和删除均保护仍在使用的文件。
- 同一数据库的导入串行查重，重复导入拒绝并提示“这本书已在书架中”，现有书架仍可见。
  已迁移的软删除书籍重导入保留内部主键；待迁移旧记录与新 ID 同值则拒绝，不错误认领数据。
- 原书缺失或已删除时无法恢复原始三元组，保留旧 ID 和用户数据，等待原文件恢复。
  坏书和身份冲突保留原数据、允许其他书迁移；迁移异常时启动跳过孤儿清理。

`_importBytes` 为既有线性导入主流程，仍超过 40 行。此次仅抽出身份迁移与导入排队，
避免同时重构已有修复、落库和取消流程；其风险由导入专项与全量回归覆盖。
