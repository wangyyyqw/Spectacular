# EPUB 引擎真机验收（2026-11-06 至 2026-11-07）

设备：MEIZU 20 / Android 16（sdk 36），序列号 `381QYGE4224AA`。
范围：EPUB 解析容错、排版与渲染的真机验证；全部结论来自真机，未使用模拟器。

## 一、改动摘要

| 需求 | 实现位置 | 结果 |
| --- | --- | --- |
| spine 断链的 EPUB 能被打开 | `packages/reader_core/lib/epub/importer.dart` 的 `recoverSpine()` | spine 为空或 itemref 全部失效时按 manifest 声明顺序恢复，并排除 `properties` 含 `nav` 的目录文档 |
| manifest 也无可用章节时仍可读 | 同上 `_scannedSpinePackage()` | 二级兜底：按文件名扫描整库 XHTML，`href` 仍走原有资源解析 |
| 恢复后的分级与提示 | `importer.grade()`、`epub_exception.dart` | 新增 `E_SPINE_FALLBACK` 判 L3，书架显示「结构异常」角标，合法 EPUB 不受影响 |
| 错误码防漂移 | `epub_exception.dart` | 补齐 `E_DUPLICATE`、`E_IDENTITY_CONFLICT`，码表 46 → 49 |
| 回归护栏 | `packages/reader_core/test/epub/spine_fallback_test.dart` | 4 例：manifest 恢复、全失效 id 恢复、整库扫描恢复且 href 可解析、无可读章节仍拒绝 |
| 基准样本 | `tests/corpus/build_device_fixtures.py` | 新增 `verify-broken-spine.epub`（spine 全指向不存在 id，nav 提供 3 章目录） |

合法 spine 路径的代码未改动：`effectivePackage` 在 `spine.isEmpty == false` 时就是原 `package`，
后续 `ResourceIndex`、`TocFallback`、`probeImport`、`grade` 收到的对象与改动前完全一致。

参考工程的取舍见[参考工程复用分析](参考工程复用分析-2026-11-06.md)：Ferrous 的
`epub_fallback_parser.dart` 被吸收为恢复策略；Reeden 的排版规格与 Readium 的分页结论
记为备选；多看固定版已在上一轮安全吸收；技术栈不兼容的自研渲染方案明确不迁移。

## 五、性能对比

口径：隔离 release 包，同一 book《诸神愚戏》（1541 章 / 148.5 MB），同一 harness
（`integration_test/reader_perf_app.dart`）；基线 `9e84d69` 与当前 `8a719d6` 使用完全相同的
测试入口与开关（`--long-scan`，远跳开启）。

| 指标 | 基线 9e84d69 | 当前 8a719d6 | 差 |

| 冷开首屏正文 ms | 3232 | 3225 | −7 |
| 冷开完全显示 ms | 3322 | 3317 | −5 |
| 冷开 RSS MB | 574.2 | 557.0 | −17.2 |
| 热开完全显示 ms | 3032 / 3056 | 3061 / 3037 | ±29 内 |

## 六、已知问题与后续建议

1. 正式包 release 构建依赖联网解析 `androidx.test:*:1.2+` 动态版本；`dl.google.com` 不可达时
   `flutter build apk --release` 会失败，本次改用 `./gradlew assembleRelease --offline`
   （本地 Gradle 缓存已具备所需构件）。建议在 Gradle 里锁定测试依赖版本或配置可达镜像。
2. 存储层在 `cfi == null` 且已有内容锚点时刻意保留旧位置（书架标「读完」不得清掉锚点）。
   测试工具写进度前必须先 `clear()`，否则会开到上一轮的章节；该约束已写入 harness 注释。
3. 长书整本扫描峰值 RSS 734 MB，关闭阅读页后回到 698 MB，未观察到明显回落。
   是否需要进一步收敛缓存需产品侧确认。
4. 目录书架的「在读」百分比与阅读页头部百分比口径不同（观察到 83.33% 与 72%），
   本次未定位是否预期，建议单独核查。
5. 断链恢复目前只用 manifest 声明顺序，可靠性有限（因此判 L3）。下一步可用 nav/NCX
   目录顺序作为更可靠的恢复来源，并对 `E_SPINE_FALLBACK` 增加一次性提示。
