# 测试分类与按改动验证

日常只运行受改动影响的测试。分类真源是 `tool/test_groups.json`，执行入口是 `python3 tool/run_tests.py`；测试仍保留在既有包目录，不因分类搬迁文件。

## 分类

| 分类 | 验证职责 | 常见改动 |
|---|---|---|
| `ui` | 界面、面板、手势、翻页、无障碍交互 | 书架、阅读菜单、设置面板、翻页动画 |
| `css` | CSS 解析、层叠、阅读覆盖、真实章节样式 | 选择器、继承、字号覆盖、CSS 值消费 |
| `layout` | 文本、盒模型、浮动、表格、分页 | 断行、边距折叠、容器几何、页边界 |
| `paint` | 正文自绘、背景、边框、装饰、像素 | 绘制顺序、裁剪、透明度、正文命中区域 |
| `resources` | EPUB、文档解析、字体图片、资源缓存 | ZIP、OPF、字体注册、资源准备、缓存生命周期 |
| `position` | CFI、进度、重定位、文本搜索 | 锚点、修订定位、进度索引、全文扫描 |
| `storage` | 数据库、书库、导入队列、偏好持久化 | drift、进度落盘、阅读时段、书评保存 |
| `perf` | 性能预算、预取延迟、基准、诊断埋点 | 内存预算、缓存调度、性能入口、日志 |
| `integration` | 公共契约、跨模块阅读链路冒烟 | 公共接口、格式接入、阅读主流程 |
| `tooling` | 本地 Python 工具回归 | 分类入口、CSS 对比、真机性能报告工具 |

分类依据是测试验证的行为。应用包里的 `css_gaps_test.dart` 属于 `css`；UI 包里的资源缓存与重定位测试分别属于 `resources`、`position`。每个测试文件只归一个主分类，多分类选择自动去重。

## 常用入口

```bash
# 默认：按暂存、未暂存及未跟踪文件选择
python3 tool/run_tests.py

# 指定职责，可组合；修改界面只跑 ui
python3 tool/run_tests.py ui
python3 tool/run_tests.py css
python3 tool/run_tests.py css layout paint

# 包含分支上相对 main 分叉点的已提交改动及当前工作区
python3 tool/run_tests.py --changed --base origin/main

# 先预览范围与完整命令，不运行测试
python3 tool/run_tests.py --changed --dry-run
python3 tool/run_tests.py --paths packages/reader_core/lib/css/cascade.dart --dry-run

# 如需静态分析，只分析所选测试涉及的 Flutter 包
python3 tool/run_tests.py ui --analyze

# 索引校验与分类清单，不启动 Flutter
python3 tool/run_tests.py --check
python3 tool/run_tests.py --list

# 显式全量：三个包的本地测试及 Python 工具回归
python3 tool/run_tests.py --all
bash tool/run_all.sh                    # 全量并分析三包
```

运行默认使用 `flutter test --no-pub`，静态分析使用 `flutter analyze --no-pub`。缺少 `.dart_tool/package_config.json` 时停止并提示在对应包执行 `flutter pub get --offline`；仅当离线缓存不足时再下载所需依赖。Python 工具分类无需 Flutter，本地 Python 字节码缓存由 Git 忽略。

工具测试使用启动入口的同一 Python 解释器。既有 CSS 图像对比测试依赖 Pillow，请使用已具备该依赖的本地环境；本项目 macOS 工具已有 `/usr/bin/python3` 入口，可运行 `/usr/bin/python3 tool/run_tests.py tooling`。缺依赖时会返回失败，不自动安装或跳过测试。

## 自动选择规则与边界

- 修改测试文件时只运行该文件；删除测试时选择原分类的剩余测试。重命名同时读取旧、新路径，避免遗漏旧职责。
- 修改源码时按 `source_rules` 选择职责。CSS 加载可能同时选择 `css`、`resources`；公共章节源或 API 涉及多个职责时扩大到明确列出的相关分类。
- EPUB 章节源码直接按 `reader_core` 的实际路径选择职责；应用和测试统一导入核心包。
- 文档与工程范围外的输入文件不触发测试。没有改动时输出“没有需要运行的测试”，不会自动执行全量。
- 未分类测试、失效索引或无法识别的源码改动会返回非零状态。依赖配置、分析规则、原生平台及真机入口需要明确判断范围，显式选择分类或补充映射；不会自动退回全量。
- `--all` 不含 `integration_test/*_test.dart` 真机入口、设备操作、语料生成及工程守卫。真机验证仍按验收模板执行；核心依赖边界变化运行 `bash tests/tool/verify_core_boundary.sh`，分析规则变化运行 `bash tests/analysis/verify_strict_flags.sh`。

自动映射是按职责建立的验证范围，不替代对调用方的判断。改变 CSS 的布局或绘制契约时增加 `layout`、`paint`；修改数据库并改变界面反馈时增加 `ui`。跨职责的公共接口、依赖升级或发布验收可明确执行全量。

## 行为变更与测试同步

1. **同一提交同步实现与预期。** 修 bug 时补充能在旧实现失败的最小回归；有意改变公共行为时同时修改相关旧断言及调用方回归。纯内部重构应保持原断言。
2. **先确认契约再更新断言。** 说明旧行为、期望新行为与依据，校验实际调用结果、尺寸、颜色、CFI 或持久化数据。不能只断言新代码内部字段，也不能为通过而删断言、扩大容差或无条件跳过。
3. **夹具跟随运行条件。** 日期使用固定或明确隔离的时段；异步测试等待真实任务及资源退出；缓存测试核验实际消费与失效行为。资源缺失的跳过必须注明条件并计入验证结果。
4. **新增、删除、重命名测试同步索引。** 检查主分类；修改 `test_rules` 和必要的 `source_rules`，运行 `--check`。规则按顺序首次匹配，具体例外置于目录规则前；路径使用 `*` 通配，可跨子目录。
5. **快照更新逐条归因。** 只有明确的行为变更才更新 fixture/golden，记录旧、新差异与原因，再用最终实现验证；禁止批量重录来隐藏回归。
6. **提交记录写实际证据。** 列出所选职责、命令、通过/失败/跳过，以及未覆盖的跨模块或真机范围。索引校验只能发现文件归类问题，测试预期是否符合新契约仍需审查。

提交前先执行 `--check` 并确认预览范围，再运行相关测试。纯文档、注释或无行为变化的样式可跳过测试，说明理由；发现范围外旧问题只记录，不在本任务顺手修改。
