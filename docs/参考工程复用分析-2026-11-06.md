# 参考工程复用分析（2026-11-06）

分析对象：`参考/` 下 8 个工程（anx-reader-develop、Ferrous-main、flutter_readium-main、
epub_viewer_pro、katbook_epub_reader-main、duokan 逆向产物、reeden、阅微）。
判定口径：「可迁移」= Spectacular 自绘管线（禁平台插件、CFI 位置体系、不改写原书）
未覆盖、或能用更低成本获得同等收益的方案；其余一律记为「不迁移」并说明原因。

## 1. 总体判定

| 参考工程 | 技术栈 | 与 Spectacular 兼容性 | 结论 |
| --- | --- | --- | --- |
| anx-reader | Flutter + WebView + foliate-js | 不兼容：文档树/盒模型只存在于 JS，Dart 无中间态 | 主链路零可迁移；只取数据模型与交互细节 |
| Ferrous | Flutter + Rust | 兼容（纯 Dart 解析），但深度低于现状 | 仅 spine 回退一项值得做（已落地） |
| flutter_readium | Dart 模型 + 原生 Readium toolkit | 不兼容：渲染/分页/CSS/TOC 全在原生 | 只取测试基建与 Locator 互操作格式 |
| epub_viewer_pro | epubx + flutter_widget_from_html | 不兼容：Widget 级 HTML 渲染 | 不迁移 |
| katbook | epubx + DOM + 自研段落模型 | 纯 Dart，最接近，但 CSS/分页质量低于现状 | 只做结构核验项，不迁移实现 |
| duokan（逆向） | 原生 | 私有扩展可对接 | CSS/扩展属性与 HTML 标签层可增量吸收 |
| reeden | 原生 | 规格文档可对照 | orphans/widows、页眉页脚槽位等增量点 |
| 阅微 | 原生 | 规格文档可对照 | 回归矩阵补强、表现属性映射 |

一句话：**没有可整体移植的分页/排版引擎**；增量集中在「解析容错、CSS 能力面、
测试方法」三类，其余照搬即反模式。

## 2. 已采纳并落地（本轮）

| 编号 | 方案 | 来源证据 | 落点 | 验证 |
| --- | --- | --- | --- | --- |
| F-1 | spine 为空/全部失效时按 manifest 章节顺序恢复阅读顺序（排除 nav 文档），降级 L3 + 诊断码，而非直接拒绝 | `参考/Ferrous-main/lib/features/reader/epub_fallback_parser.dart:63-79` | `packages/reader_core/lib/epub/importer.dart`（`recoverSpine`/`_scannedSpinePackage`）、`epub_document.dart`（`_finishOpen`）、`epub_exception.dart`（`E_SPINE_FALLBACK`） | 单测 `test/epub/spine_fallback_test.dart` 4 例；fixture `verify-broken-spine.epub` 真机场景 S6 |
| F-3 | EPUB 按中央目录随机访问，章节/图片/字体按路径读取，不先解压整本 | `参考/阅微/analysis/import/sources/app/zhendong/reamicro/arch/EpubFileManager.java:71-88`（`Okio.openZip` + `source(path)`） | 自研 `packages/reader_core/lib/epub/zip_source.dart`（中央目录索引、文件/内存双后端、按需 deflate、CRC 校验）；`EpubArchive.fromFile()` / `openEpubFile()` 接入阅读与导入 | ZIP 回归 20 例；真实 148.5 MB EPUB 真机性能：冷开 1476 ms，导入完成 PSS 110.1 MiB、峰值 HWM 290.0 MiB |

补充说明：Ferrous 只做「manifest 顺序」一级；本实现补了二级「整库文件扫描」兜底
（manifest 无章节时），并保持 `E_SPINE_EMPTY` 拒绝口径不变——无可读章节依旧拒绝。

F-3 没有直接引入 Okio/Kotlin 依赖：Spectacular 是纯 Dart 自绘管线，改用
`RandomAccessFile` 与本地 ZIP 解析即可获得同等随机访问能力，避免跨栈依赖。
ZIP64、加密和特殊压缩等变体继续回退 `package:archive` 整本解码，但设置 512 MB
上限，防止异常容器把内存峰值重新放大。

## 4. 明确不迁移（反模式与不兼容）

- **WebView/JS 桥链路**（anx-reader、flutter_readium 原生侧）：与「自绘分页 + CFI 位置 +
  禁平台插件」冲突，且内存/首屏不可控。
- **软连字符/首行缩进注入**（Ferrous `hyphenation_helper.dart:83-152`）：注入 U+00AD
  会改变文本偏移，破坏 CFI/选区/搜索索引；Spectacular 已有排版期断字与缩进。
- **全书一次性解析常驻、静态无界缓存**（Ferrous）：与现状 LRU + 指纹缓存相比是倒退。
- **导入即解压整本资源到目录**（阅微 `PlatformArchiveExtractor`）：收益是随机访问，
  但会放大磁盘与首次导入时间；Spectacular 改为在 ZIP 内按需读取，不额外展开。
- **导入期改写 XHTML**（阅微 `HtmlOptimizer`）：与「不改写原书」决策冲突。
- **BookmarkModel 字段映射**（anx-reader `models/bookmark.dart:32` 把 percentage 写进
  color）：数据模型缺陷，不要照抄。
- 通用差异（不等于缺陷）：竖排、复杂表格、浮动、ruby 的能力面 Spectacular 覆盖更宽；
  其余参考工程在这些维度均未超过现状。
