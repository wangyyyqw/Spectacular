## 一、范围与产品行为

性能修复、章节源职责拆分、UA 治理与分页路径统一合并实施。保留现有 CFI、书签、标注及原始阅读锚点，字节进度算法与锚点语义版本独立。

- 取消阅读路径的全书精确字数扫描，包括开书与比例计算中的隐式扫描。导入时已有字数字段不被字节权重污染。

上一版关于默认孤行／寡行 2/2、约束继承、候选回退器的实施任务已全部取消；不以更新 golden 方式掩盖旧贪心行为的回归。

## 三、进度、首屏与分页规则

### 3.1 轻量进度

从 ZIP 中央目录读取章节 XHTML 未压缩大小，旧归档后端只读条目 `size`。

```text
全书比例 =（此前章权重和 + 本章权重 × 本章原文位置比例）÷ 总权重
```

已落盘的 `packages/reader_core/lib/position/book_progress_index.dart` 中，`BookProgressIndex` 保存不可变权重、前缀和、排除集合，`algorithmVersion = 1`；显示、跳转、保存、书架恢复共用。app 的 `book_progress.dart` 从 `archive.uncompressedSizeOf` 建索引，`ChapterPositions` 管理单章原文坐标。章内比例由聚合原文 CFI 偏移／长度提供，仅准备目标章。纯图片章使用真实可定位元素的文档顺序。目录、非正文、确认缺失章节沿用已有排除策略；大小元数据不可用时全书按可读章等权降级。

百分比跳转先用权重二分定位目标章，再通过 `AsyncPositionedChapterSource.prepareCfiForReadingPercent` 异步准备该章坐标。`ensureCharacterIndex` 生产入口、任务与 `_weightsForPosition` 全书兜底已移除。旧百分比首次可校正一次，原始 CFI 与标注不迁移、不删除；搜索仍可按需读取章节纯文本，不参与百分比分母。

### 3.2 一次首屏排版

内容准备与封面动画同时启动。顺序固定为：恢复 CFI → 目标章结构 → 原文核验本章装饰与字体加载 → 冻结布局输入 → 完整排版 → 同次提交正文与两个进度数字。

实际接口为 `AnchorChapterSource.loadAnchorChapter`；`PreparedChapterSource.setChapterPreparer` 登记每章冻结前的装饰与字体核验，装饰核验不调用 `loadChapter`。`BookOpener` 的封面与阅读页共用路由，`EpubReaderPage` 并行启动来源打开、初始设置与字体准备。其他章的装饰随请求准备；纯颜色、标注与自动规则只重绘。滚动首屏只等当前章，邻章稍后补入。源的 `chapterLayoutCount`、`anchorPreparationCount` 和真实字体回归用于确认目标章一次排版；这些功能证据不替代首屏完整可见耗时。

### 3.3 统一断页语义

在级联竞争前把 `page-break-before/after/inside` 放入 `break-before/after/inside` 的同一槽位；`always` 归一为 `page`。特异性、来源、重要性、声明顺序、变量与 CSS-wide 关键字继续沿用现有层叠。直接构造 `ComputedStyle` 也走同一归一入口。

`CssFragmentation` 已在层叠竞争前归一属性／值，并为直接构造 `ComputedStyle` 提供同一入口；`orphans/widows` 不进入计算样式，包括作者的 `!important`。普通与流式 `Paginator` 已共用 `_paginateSteps`。app 的 `ChapterPageLayout` 普通分支消费 core 流式入口，浮动仍由同文件内独立的 `_FloatPagination` 状态机处理，复用断页字段及表格切片工具。保留合法正文断点、强制 break、图题组、表头、容器续框、标题避页底、竖排与多列行为；不能将此状态写成“所有浮动算法已迁入 core”。

本次别名竞争、`avoid-page` 与流式分页语义接入已将 `PageIndex.currentSchemaVersion` 提升为 6，旧 v5 结果拒绝复用；纯职责迁移不另行升级。只有结构化等价证据充分时才删除旧补丁和过渡实现。

## 四、工作包 U：UA 样式治理

### 4.1 保留既有结构

当前 `uaStylesheetCss` 与 `UaBlockDefaults` 继续并存。源码已为 78 个声明块登记 `UA-001`～`UA-078`，`docs/UA规则台账-2026-11-07.md` 记录来源、消费状态与两入口差异：

- `uaRules()` 是完整规则集，供 `Cascade.compute` 使用；
- `UaBlockDefaults` 是部分旧块级覆盖层，只含当前排版/绘制栈已消费的物理属性。

不能在没有调用方清单时直接删除 `UaBlockDefaults`，也不能要求两条入口对所有标签输出相同声明。

每项规则或不可再拆的规则组应记录：

- 稳定 ID；
- 规范名称与锚点；
- 默认值理由；
- 项目差异；
- 实现消费者；
- 支持状态；
- 测试 ID；
- 原始顺序号。

例如实际 ID `UA-019` 对应 `h1`：字号/段距来自 HTML 建议，避页底是阅读器增强，作者仍可覆盖。规则 ID 不因逻辑分组或规范章节变化重新编号。

### 4.2 逻辑分组

| 分组 | 内容与取舍 |
|---|---|
| HTML 15.3.1 | 隐藏元素、`hidden`、`noscript`、`dialog`；明确脚本禁用策略 |
| HTML 15.3.2 | `html`/`body`、页面默认边距；区分规范建议与阅读器接管 |
| HTML 15.3.3 | `p`、`blockquote`、`figure`、`pre` 及遗留表现属性 |
| HTML 15.3.4 | `strong`/`em`/`code`、上下标、装饰、`nobr` |
| HTML 15.3.5 | `bdi`/`bdo` 及 `unicode-bidi`；区分解析支持与实际布局支持 |
| HTML 15.3.6 | 分节/标题字号段距；断页增强另标项目来源 |
| HTML 15.3.7 | 列表、缩进、marker 与嵌套；记录 flat 近似 |
| HTML 15.3.8 | 表格、单元格、caption 与表头 |

| Reader policy | `flow-root`、`overflow`、正文区约束与私有契约，不伪装成规范强制 |

章节号只作辅助定位，必须同时保存稳定章节标题或 URL 锚点。WHATWG 是可更新文档，不能只写数字让未来维护者猜版本。

### 4.3 保序原则

CSS 源顺序参与层叠。按规范编号搬动规则不天然行为不变，`pre`、`body`、列表和属性选择器可能重叠。

- 已完成的源码治理只补注释和台账，保持选择器、声明、`!important` 和输出顺序不变。
- 后续分文件/常量分组时，逻辑分组与发射顺序分离：规则保留原始 ordinal，最终拼接按已审计顺序。
- 对确有必要重排且能证明交换无影响的规则，逐项记录冲突分析并通过 computed-style 差分。

### 4.4 双入口与支持状态

每个规则标记为：

- 仅保存声明；
- 已参与计算样式；
- 已影响布局/绘制；
- 兼容近似；
- 暂不支持。

不要把字符串出现当成可见行为。对 `UaBlockDefaults` 只验证其承诺子集：标题、引用、列表、表头、`hr` 等与完整路径的计算效果；有意差异写明理由。

原规则数 ≥30 的测试仍保留；已新增更强的护栏：78 个声明块、127 条声明、连续唯一 ID，以及去注释／空白后 SHA-256 `22d62e368e424e8ddfde03d77daa242a999ae27244d2833d78d72ed53d79263a`。`ua_stylesheet_test.dart` 验证作者覆盖与两入口承诺子集，`fragmentation_cascade_test.dart` 验证别名层叠。固定摘要只证明声明及顺序保留，不能充当全部规则的可见行为覆盖。

## 五、工作包 R：章节源拆分

### 5.1 目标与红线

目标是降低变更波及范围、减少隐式状态和缩短测试依赖链。

参考警戒线：

- 门面约 500–800 行；
- 内部编排方法约 150–250 行；
- 一般文件约 300–800 行；
- 复杂表格/浮动模块超过 1000 行时必须有独立算法边界与拆分理由。

这些是评审警戒线，不是通过缩行、合并语句就能达成的指标。

禁止：

- `part`、`mixin` 和公开全部字段的假拆分；
- 新增万能 `Context` 让所有模块读取全部状态；
- 改变数据结构却无意改变遍历顺序、计数器作用域、CFI 坐标或缓存拥有者；
- 用 107 个空壳类或把原巨类整体搬进 Builder。

### 5.5 依赖方向与编排

```text
门面
  → 结构／原文准备与目标章装饰／字体就绪
  → 冻结 LayoutSnapshot 与 PreparedChapterLayout
  → ChapterLayoutScheduler 同键共享作业
  → ChapterLayoutPipeline：walker 构块 → 容器收尾 → ChapterPageLayout
  → CompletedChapterLayout.createAsync：冻结顶层列表并估算持有图
  → generation 与实际字体依赖复验
  → 门面 _commitLayout：完成缓存与当前配置计数
```

- builder 依赖样式、行内、图片、表格、容器等窄端口；
- table 可依赖 inline 测量，inline 不可反向依赖 table；
- 任何内部模块不得 import `EpubChapterSource` 或持有它；
- `reader_core` 继续拥有 `Cascade`、普通／流式 `Paginator`、页索引和表格网格算法；app 承担 EPUB 适配与已有浮动状态机。`PageIndex.fromAsync/encodeAsync/decodeAsync/applyAsync`、`TableGridLayout.createAsync`、`Paginator.tablePieceAsync` 均有真实 await 调用点，同步兼容入口共享工作步骤。

特殊页面快路也返回“产物候选”，避免在分析函数内先写页索引、之后才检查作业过期。取消/缺章/失败应是内部明确状态，由门面映射回现有公开契约，不用同一个空列表隐含四种含义。

### 5.8 缓存、字体与生命周期

完成页面、流块、固定块与页索引由同一 `CompletedChapterLayout` 持有，`ChapterLayoutCache.recent` 是进程内纯结果 LRU，最多三项、估算 32MiB。键含内容版本、完整基础样式、章节、几何／上内缩、overrides、该章度量覆盖、实际字体依赖及间距／页索引版本。`BoundedCache` 只用于有界准备数据与细粒度测量，不承担完整布局的独立资源关闭。

基础样式由 `chapterBaseStyleKey` 在每个来源首次使用时计算一次稳定签名，覆盖113个语义字段及嵌套值；Map／Set排序、列表保序、颜色和长度保留完整语义。该签名同时用于完整布局配置与两种页索引依赖，避免CSS变量或行高继承不同却复用旧页面。阅读器主题覆盖仍走只重绘路径；源码现有约定仍要求来源存活期间不原地修改基础样式的公开集合。新键使旧配置的布局及页数缓存自然失效，不迁移旧错误结果。

生产 pipeline 已 await `CompletedChapterLayout.createAsync(..., checkpoint: budget.checkpoint)`；同步 factory 只作兼容，共用同一遍历。估算按对象身份去重，覆盖内盒 `PageBlock` 载荷、表格格内布局、脚注／ruby／样式字符串及可识别图片字节缓冲区；字节视图按完整底层缓冲区计。17Mi 个中文字符的内盒估算 35,654,166B，超限拒收；三处共享 12MiB 缓冲区只计一次。`withPageIndex` 复用已有估算并调整索引差额，不再同步重扫整章。32MiB 是可识别纯布局持有图的估算上限，不是进程、图片解码、原生字形或 GPU 总内存硬限。

`BookFonts.ensure` 后复验 generation；`freeze` 在映射、可用性与 `FontCoverageRegistry.revision` 不变时复用同一 `BookFontView`。提交时先比较视图身份，否则只验证本章实际引用字体族的依赖。字体注册不直接提升布局 generation，避免触发注册的作业自行过期；书级计页键另外包含请求的用户字体集合／环境与实际可用性。

fixed 覆盖在普通、浮动及成功索引回放路径均经同一异步收尾；此前回放遗漏已红测确认并修复。快路只返回候选，经预算和依赖复验才提交。字体、索引损坏、共享等待者和取消继续保留直接回归。

`close` 清理本来源准备状态、映射和细粒度缓存，归档只关一次，重复关闭安全；近期纯布局可继续在上述 LRU 内复用。准备worker的取消／退出、端口释放、同键重建不被旧结果覆盖已通过回归。Flutter 已注册字体由引擎持有，不能承诺同步卸载全部原生字体。

### 5.9 CFI 与文本变换不变量

源码实际使用 CFI 与 UTF-16 坐标，不能把源码 `sourceSpan`、聚合纯文本索引、显示文本偏移和 CFI 字符偏移混为一个值。

坐标模块需区分：

- XHTML 源码位置；
- 聚合原文；
- pseudo/quote 插入后位置；
- 首字或浮动摘除后位置；
- 分页子串位置。

删除并非天然可逆，生成内容也未必有原文位置；必须明确前/后边界吸附策略，而不是承诺双射。章内位置比例使用目标章聚合原文的 CFI 偏移与长度，纯图片章使用真实可定位元素顺序；不能混用原始 XHTML 去标签长度、显示文本或像素偏移，也不能为进度扫描全书字符。

纯重构验收时，每页首末 CFI、命中字符、选区、脚注和装饰锚点必须等价。图片位置修复是已批准的有意差异：旧 null 或聚合器写入的伪父 CFI 可改为经原解析树确认的真实 `img/image/object` 叶元素；旧父／SVG 兼容仅映射唯一可见图片后代。原已指向真实正文／图片的 CFI 继续精确等价，不能全局跳过 CFI 对照。新分页语义只允许改变页边界，不改变所指正文内容。

## 六、作业、缓存与全书计页

### 6.1 不可变作业与调度

实际单次排版作业是 `ChapterLayoutScheduler` 的私有 `_ChapterJob`，持有冻结的 `LayoutSnapshot`、有效等待者与本次 `LayoutBudget`；构块状态由 pipeline 每次创建。完整布局键包含内容版本、章、几何与正文上内缩、排版设置、实际字体依赖、该章装饰度量、间距版本与页索引 schema。

`ScheduledChapterSource.scheduleChapter` 返回独立可取消句柄；同章同布局键共享在途计算，取消一个等待者不取消其他有效等待者。新的设置、旋转、定位与关闭使旧任务立即失效，提交前再次验证请求与字体依赖。

优先级为 `reading > prefetch > pageCount`。`LayoutBudget` 已按当前阅读 4ms 一片、预取与全书计页每帧目标 2ms 调整；后台等待可被取消或提升为前台唤醒，不能只把 `pageCount` 当后台。文字逐行、节点／行内遍历、格内测量／min-content、网格槽位、表格切片、页索引、容器收尾及完成缓存估算均有预算入口。

共享作业的阅读等待者取消后，调度器重新检查队列并允许已排队的高优先级请求抢占降级作业；先取消预算再取消等待者，避免同步取消回调重入。同级请求不抢占，旧作业退出后才运行下一项，提交前继续复验预算。

预算为协作检查：一次原生文字测量、磁盘读取、CSS 选择器匹配或其他原子步骤仍可能越过目标片长，不能根据配置值宣称最长 UI 阻塞已通过。正常 ZIP 的目标章节／直接脚注定义／CSS 解压、文本解码与解析已在同一数据 worker 执行；准备共享、抢占、实际worker退出及取消不回填已有直接回归。Flutter 文字测量仍留主 isolate，legacy特殊压缩与开书元数据读取仍同步。

### 6.2 度量与缓存

标点候选行避免重复测量；只有可证明首尾／跨行调整不影响的行才复用基线。混合字体、ruby、禁则、坐标与留白结果不能近似替换。

字号改变已按完整键选择结果，主题颜色继续只重绘；近期完整结果最多 3 项、估算总容量 32MiB，优先当前章和上一字号。大于预算的条目不进入近期缓存。`EpubReaderPage.didHaveMemoryPressure` 真实调用非当前布局清理；关闭取消任务并释放书籍资源。候选测量复用与异步分片已有等价证据，但完整 fresh 字号测量尚未证明达到性能门槛。

### 6.3 独立页数状态

`reader_ui/book_page_count.dart` 的 `BookPageCountState` 已提供布局键、完成页数、完成章节数、章节总数、状态与失败章；label 区分“已排 N 页”与“全书 N 页”。`BookPageCounter` 首屏提交后启动，当前章结果直接计入；后台通过同一 `scheduleChapter(priority: pageCount, retainResult: false)` 逐章排版，完成一章只保留章页数与完成状态，不常驻全书页面。

每章完成累计，界面通知最多每 250ms 一次。退出或退后台暂停，重新进入可续算。失败章保持未完成，下次打开重试；部分结果不能标成完整，也不能作为阅读百分比分母。

`storage/drift_book_page_count_store.dart` 的 `DriftBookPageCountStore` 已复用 settings 按书籍内容版本与完整布局键存储，每本书最近两套配置；源通过 `setPageCountStore` 绑定并可 flush。晚绑定恢复保留通知器身份，实测当前章覆盖旧缓存；旧存储／布局／关闭后的结果不串值。字号变化切换缓存，无有效缓存从 0 重新累计，失败章不标完成。真实字体与绑定回归已通过，仍须在最终 app 全量和同设备阅读流程验证。

## 八、性能验收与未处理风险

同设备、同字体、同样本、同 Release 入口前后各 5 次独立进程，每次 `--rounds 1 --resize`，分别保存报告；每次记录首次开书、首次新字号、缓存恢复、首屏完整可见与最长连续 UI 阻塞。两版本采用相同的停止／启动流程，性能采样不与其他测试并发。

实际自驱动入口会在计时前下载、校验原书并读章节数，因此开书仍是“文件已预读后的进程内初开”，不宣称冷文件开书。原 `--rounds 5` 在同一进程中初开一次、重开四次；完成布局跨来源关闭保留，第二至第五轮的22号可能直接命中缓存，不能把其五轮中位数作为新字号冷排结果。该模式仅供热重开／热缓存补充观察，不混入正式门禁。

正式统计分别取五份独立报告的 `open_0`、`resize_0_22.0` 和 `resize_0_21.0`，核对源码、入口、原书、设备与字体／尺寸完全一致，并核验每份报告 `process.rounds=1` 及独立启动记录。进程ID可能被系统复用，需同时保留启动时间与宿主的停止／启动日志。前后均使用当前入口；不能用人工清缓存模拟独立进程，也不能混合旧入口或不同温度的样本。`text_ms` 是正文帧就绪，`complete_ms` 还要求封面揭开和正文淡入结束，均不等同系统实际呈现时刻。4ms定时器最大间隔用于连续UI阻塞的保守观察，包含正常调度间隔；build／raster仅在 `frame_timings_complete=true` 时具有尾部已交付证据。
