# P2-03 测试报告：行级对齐

> 日期：2026-10-23　执行人：Lead　任务：P2-03（3h）
> 依赖：P2-02　参考：技术方案 §8.4、§61.5；阅微 `ContentDom.adaptiveJustify`

## 1. 实现

- 对齐在布局阶段算完，绘制阶段只按结果落笔
  - `LineBox` 新增 `offsetX`（行在内容区内的水平偏移）与 `justifyExtra`（justify 待分摊余量）；
  - `TextLayoutEngine` 断行测量不再把 `textAlign` 传给 `TextPainter`，行宽一律取自然宽，再由 `_align()` 按 `text-align` 计算偏移：
    - `left/start`：`offsetX = indent`；
    - `right/end`：`offsetX = indent + (可用宽 - 行宽)`；
    - `center`：`offsetX = indent + 余量 / 2`；
    - `justify`：`offsetX = indent`，余量写入 `justifyExtra`；
  - 可用宽 = `maxWidth - 行首缩进`，首行缩进与居中/右对齐可以同时生效。
- justify 只拉伸该拉伸的行（§61.5、§8.4）
  - 末行、硬换行行 `justifyExtra = 0`，保持 start 对齐；
  - 行内没有可拉伸间隙（例如单个长英文单词）时同样不拉伸。
- 间隙规则（`lib/text/justify.dart`）
  - 取相邻字符之间的间隙，末字之后不设间隙，因此右缘不会多出一个 `ls`；
  - 跳过含换行的间隙；
  - 跳过两侧都是拉丁字母/数字的间隙，不拆英文单词；
  - 含 CJK 的行按字间隙分摊；不含 CJK 的行只拉伸词间空格。
- CJK 判定（`lib/text/script.dart`）
  - 按 Unicode 区块判定：基本区、扩展 A/B+、兼容汉字、CJK 符号与标点、假名、谚文、全角字符；
  - 阅微 `isCjk` 把 `0 <= c < 42720` 全部算作 CJK（连 ASCII 都是），这里按 §16 的有意差异修正。
- 绘制（`PagePainter`）
  - 逐间隙给“间隙左侧字符”加单字符 `SpanStyle`，`ls = justifyExtra / gaps.length`，保留原 `letterSpacing`；
  - 行的水平位置直接用 `line.offsetX`；`contentWidth` 参数不再需要，已删除。

## 2. 与阅微的对照

阅微 `ContentDom.adaptiveJustify` 的做法（静态分析资料 `analysis/.../ContentDom.java:3473`）：

- 只在 `text-align: justify` 且文本含中文时介入，末行/`justifyLastLine` 除外；
- `extra = maxWidth - getLineRight(行)`；`getLineRight` 已含 Compose 的对齐结果；
- `gaps = cjkJustifyGapIndices(行文本)`，`ls = extra / gaps.size()`，给每个间隙左侧字符加单字符 `SpanStyle.letterSpacing`（叠加原字距）。

我们采纳与不同的部分：

| 维度 | 阅微 | 我们 |
|---|---|---|
| 对齐位置 | 交给 Compose 的 `ParagraphStyle.textAlign`，自己只补 justify | 逐行自绘，布局阶段算 `offsetX`；相当于自己实现 `getLineRight` |
| justify 判定 | 段落级 `hasChinese` | 行级：该行有可拉伸间隙才拉伸 |
| CJK 范围 | `0 <= c < 42720`，ASCII 也算 CJK | 按 Unicode 区块判定，ASCII 不算 |
| 无 CJK 的行 | 不处理 | 拉伸词间空格 |
| 余量来源 | 已对齐的右缘 | `maxWidth - indent - 行宽` |

## 5. 已知限制

- 无 CJK 且无词间空格的行（长英文单词、纯数字）不做 justify，右缘留白；这是不拆词前提下的必然结果。
- 逐间隙单字符 `SpanStyle` 会让 justify 行按字数拆成多个 span；后续 P2-20 会评估绘制开销与取整精度。
- 间隙规则目前是通用规则，尚未按标点边界细分；P2-19 用纯中文 19 gap 与混排样本固化。
- 行内有 ruby/图片占位时，间隙仍按字符计算，ruby 覆盖层未参与（P5）。
- 竖排与 RTL 未接入，`offsetX` 只按水平 LTR 计算。
