# P2-04 测试报告：行高边界条件

> 日期：2026-10-23　执行人：Lead　任务：P2-04（2h）
> 依赖：P2-03　参考：技术方案 §61.1、§61.2；阅微 `ContentDom.maxInlineLineHeight` / `onContent`

## 1. 实现

- 行内样式区间（`StyledRun`）
  - `TextLayoutEngine.layout` / `LineBreaker.layout` 新增 `runs` 参数：为 `[start, end)` 指定独立 `ComputedStyle`，未覆盖部分沿用块的样式；
  - `TextLayoutResult.runs` 保存归一化后的区间（排序、裁掉越界、丢弃空区间），供绘制复用；
  - `buildStyledSpans` 统一把文本切成连续 span，测量与绘制共用同一套切分。
- 行高取该行最大值
  - 行高仍以 `LineMetrics.height` 为准（S1 已证等于 `fontSize × lineHeight`；多 run 时引擎取该行最大值），不再由我们二次推算；
  - 大字号 run（24px×1.5=36）或多倍行高 run（16px×3.0=48）只抬高所在行，相邻行保持 24px。
- 空行与 `br`
  - 段内空行（`a\n\nb`）保留一行行高；
  - 段尾换行剥离（与阅微 `content.endsWith('\n')` 循环剥离一致），`a\n` 只产出 1 行，避免段尾多出一个空行；
  - `<br>` 转成的 `\n` 仍标记 `isHardBreak`，不参与 justify（P2-03）。
- 空段落
  - 空文本产出 0 行、高度 0，由上层按块间距处理。
- 绘制
  - `PagePainter` 按 `layout.runs` 分段绘制；justify 行逐字符铺开，样式区间与间隙字距同时生效。

## 2. 与阅微的对照

阅微 `ContentDom`（静态分析资料 `simple/sources/org/epub/html/node/ContentDom.java`）：

- `maxInlineLineHeight(children)` 递归取 `max(fontSize × lineHeight)`（`:1016-1035`）；
- `onContent` 里先找 `br` 子节点，命中才把段落 `ParagraphStyle.lineHeight` 抬到 `maxInlineLineHeight`（`:840-841`）；
- 内联图片占位：取所有 placeholder 的最大高度，超过行高时同样抬升整段（`:927-936`）；
- 内容末尾的 `\n` 循环剥离（`:56-58`）。

我们采纳与不同的部分：

| 维度 | 阅微 | 我们 |
|---|---|---|
| 取值粒度 | 段落级：一段内最大行内行高，抬升整段 | 行级：引擎按行取最大值，只影响该行 |
| 触发条件 | 只有含 `<br>` 的段落才检查内联行高 | 每段都按行计算，无需特判 |
| 段尾换行 | 循环剥离全部 `\n` | 同左 |
| 图片占位高度 | 计入段落行高 | 暂按文字行高，图片高度等图片度量任务接入 |
| 空段落 | 由 `p` 的 margin 兜底 | 0 行 0 高，块间距由上层给 |

## 4. 验收对照（5 类边界，误差 <0.01px）

| # | 边界 | 预期 | 实测 |
|---|---|---|---|
| 1 | 空段落 | 0 行、高度 0 | 通过：0 行、0 |
| 2 | 段内空行 | 空行占一行行高 | 通过：3 行各 24，总高 72 |
| 3 | `br` 硬换行 | 行数+1、行高不异常；段尾不产生空行 | 通过：`a\nb` 2 行 24；`a\n` 1 行 |
| 4 | 混排字号 | 行高取该行最大值，不影响其它行 | 通过：24px run 所在行 36，前一行 24 |
| 5 | 超出行高的行内元素 | 撑高所在行，相邻行不变 | 通过：`line-height:3` 所在行 48，其余 24 |

## 5. 已知限制

- 行内图片占位 `U+FFFC` 还没有显式高度，行高仍按文字算；图片实际高度要等图片度量任务接入后才能撑高行。
- `runs` 由调用方传入，内部会排序；区间重叠时按先到先得，不做 CSS 层叠合并（样式层负责不产生重叠）。
- 段尾换行全部剥离，`<pre>` 末尾的空行也会被去掉，与阅微一致，属有意行为。
- 跨页切片复用原行框，行内样式区间不随切片重建（与 P2-02 尾段限制相同）。
- 竖排/RTL 未接入，`runs` 只按水平 LTR 处理。
