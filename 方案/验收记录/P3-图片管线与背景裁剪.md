# 图片资源接入与背景裁剪（P3 M2 前置）

> 日期：2026-10-24　执行人：Lead
> 范围：图片解码缓存接入生产路径 + `background-origin/clip` 语义（P3-07/08/09/11 的前置部分，未按完整验收计进度）

## 1. 实现

### 1.1 解码缓存（`packages/reader_core/lib/paint/image_cache.dart`）

- `DecodedImageCache`：键为图片 URL，按 LRU 淘汰（默认 16 条 / 48MB，字节按 `宽×高×4` 估算）；
- 解码走 `ui.instantiateImageCodec(bytes, targetWidth: displayWidth × DPR)` 降采样，避免整张大图进内存；
- 同步 `lookup(url)` 供绘制路径取图（未解码时返回 null，由 painter 跳过）；
- `prefetch(urls)` 批量预取并返回新增张数；`revision` 每解码成功 +1，宿主据此触发重绘；
- 字节缺失、坏图、解码异常一律返回 null，不抛异常（容错：技术方案 §12）。

### 1.2 UI 生产接线

- `packages/reader_ui/lib/reader_page.dart`：新增可选 `imageCache`；`PagePainter.imageLookup` 直接用 `cache.lookup`；每页首次渲染后收集 `block.style.backgroundImage` 并 `prefetch`（显示宽 = 内容区宽、DPR 取 `MediaQuery`）；解码完成触发 `setState`，`CustomPainter` 以 `imageRevision` 判定重绘（占位 → 真图不跳动）。
- `apps/reader_mobile/lib/reader/epub_reader_page.dart`：打开 EPUB 后创建 `DecodedImageCache`，加载器按「原样路径 → OPF 目录解析 → 各 spine 章节目录（最多 64 个）」的顺序在归档里找字节；页面销毁时清缓存。

### 1.3 背景 origin/clip

- `ComputedStyle` 新增 `backgroundClip`（border-box / padding-box / content-box / text，默认 border-box）；
- `PagePainter`：背景色与背景图都先按 `background-clip` 裁剪；背景图的 `size/position` 以 `background-origin` 矩形为基准（border-box 不内缩、padding-box 扣边框、content-box 再扣内边距）；`clip: text` 暂按 padding-box 降级。

## 2. 与阅微对照

| 维度 | 阅微 | 我们 |
|---|---|---|
| 背景裁剪 | `CSSBackgroundNode.computeBound(clip)` 按 clip 取矩形，origin 决定定位基准 | 同样的 clip/origin 矩形分解，`text` 降级 |
| 图片解码 | `CSSBackgroundNode.getOrRequestBitmap`（异步、按显示尺寸请求） | `DecodedImageCache`：异步解码 + `targetWidth` 降采样 + LRU |
| 绘制取图 | 缓存节点内查表，命中即画 | `lookup(url)` 同步查表，未命中跳过（占位待 P3-09） |
