## 2. 层叠顺序

| 层级 | 来源/重要性 |
|---:|---|
| 0 | UA 正常 |
| 1 | 作者正常 |
| 2 | 作者 `!important` |
| 3 | 内联正常 |
| 4 | 内联 `!important` |

同层内比较四元组特异性，再比较文档顺序（后声明胜）。

> 注：按方案 §7.2，内联正常优先于作者 `!important`；这与标准 CSS 的“作者 important 高于内联正常”不同，属于阅读器覆盖层的既定策略，已在代码注释中说明。

## 4. 覆盖的 20 组

1. UA 正常 < 作者正常；
2. 同来源同特异性后声明胜；
3. class > 标签；
4. id > class；
5. 作者 `!important` > 高特异性普通声明；
6. 内联正常 > 作者正常；
7. 内联正常 > 作者 `!important`（方案口径）；
8. 内联 `!important` 最高；
9. `div p` < `.note`；
10. 同特异性后规则胜；
11. 继承 `color`；
12. 继承 `font-family`；
13. 继承 `list-style-type`；
14. 非继承 `margin` 不传递；
15. 子元素显式声明覆盖继承；
16. `inherit` 取父值；
17. 内联 `font-size`；
18. 同规则内后声明胜；
19. 同为 `!important` 后规则胜；
20. 来源优先于特异性（作者低特异性胜 UA 高特异性）。

## 5. 与阅微的对照

- 阅微 `Style.compute(parent)` 把计算顺序硬编码成 11 段，`fontSize` 最先；继承清单 18 项（含 `customProperties`、`hasExplicitTextColor` 两个状态位）。
- 阅微的特异性是简化分数（`.a.b` 与 `.a` 同为 10），同规则内 `!important` 会被后声明覆盖，`@import` 顺序颠倒；这些缺陷不继承。
- 本实现把“比较键”抽成 `(level, specificity, order)`，并保留 18 项继承清单；计算顺序/单位换算留给 P1-21。

## 6. 顺带修复

编写用例时发现 `CssParser` 用 `expression.span.text` 取值，只拿到表达式第一项：

- `font-size: 20px` → `20`（丢单位）；
- `margin: 1em 0` → `1em`（丢第二项）。

已改为读取整条声明 span，去掉属性前缀、尾分号和 `!important`，现在得到 `20px`、`1em 0`。该修复影响所有后续层叠/样式计算，已用 CSS 与层叠测试覆盖。
