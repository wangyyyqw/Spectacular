# P7-05 诊断码体系落地（码表文档）

> 任务：P7-05 ｜ 日期：2026-10-24
> 设计依据：技术方案 §82.4（code × category × severity + detail）；形态对齐 Reeden「30 个稳定诊断码 + severity(info/warning/error) + offset 随文档缓存」（`参考/reeden/reports/500-spec-parse.md` §0-#8）
> 实现：`packages/reader_core/lib/epub/epub_exception.dart`；防漂移单测 `test/epub/epub_code_table_test.dart`
> 结论：现有 18 个错误路径全部登记（分类/严重度/出处），预留 12 码覆盖 §82.4 全表；`EpubException` 保持 const 兼容，分类与严重度从码表派生。

## 1. API 形态

```dart
enum EpubErrorCategory { opening, layout, resource, annotation, tts, io, unknown }
enum EpubErrorSeverity { fatal, recoverable, informational }

class EpubException implements Exception {        // 抛出（现有 18 处调用点零改动）
  const EpubException(code, message, {detail, offset});
  EpubCodeSpec? get spec;                          // 码表条目
  EpubErrorCategory get category;                  // 未登记 → unknown
  EpubErrorSeverity get severity;                  // 未登记 → fatal（宁严勿漏）
  EpubError toError();                             // 结构化记录
}

class EpubError { code, category, severity, message, detail, offset, isFatal }
class EpubCodeTable { specs; byCode(code); }       // 唯一事实来源
```

三条纪律（§82.4，写入源码文档）：① code 稳定不随文案变（本地化只改 message）；② 只有需要分支处理的才升 code，其余进 `detail`；③ informational 也要可见（书籍详情展示，不弹窗）。

## 4. 防漂移机制

`test/epub/epub_code_table_test.dart` 五例：
1. 码表无重复、30 条、分类非 unknown、预留码带 `P\d-\d\d` 任务号；
2. **扫描 `lib/**/*.dart` 的 `'E_*'` 字面量必须全部在表**（使用未登记 = 漂移，CI 拦截）；登记未使用 = 预留（合法）；
3. 分类/严重度派生断言（含未登记兜底 unknown/fatal）；
4. `toError` 保留 detail/offset、toString 格式不变；
5. `byCode` 索引断言。
