# P2-28 测试报告：性能预算校验

> 日期：2026-10-24　执行人：Lead　任务：P2-28（2h）
> 依赖：P2-26　参考：技术方案 §11.2（预算表）

## 1. 产出

| 文件 | 作用 |
|---|---|
| `packages/reader_core/test/bench/budget_test.dart` | 可执行预算断言：单页构建 <8ms、缓存命中 <4ms、首屏 <1s |
| `tool/bench/budget_check.dart` | 预算检查脚本：运行上面的测试、解析 `BUDGET` 行、写基线文档、超预算时退出码 1 |
| `方案/验收记录/性能基线.md` | 脚本生成的性能基线（时间、环境、三项指标、整体结果） |

## 2. 实现

- 预算口径：
  - **单页构建**：20 段 × 100 字，完整「段落布局 + `Paginator` 分页」，5 次取中位数，排除首次 JIT 与字体加载（预热一次）；
  - **缓存命中**：同一段落用 `TextLayoutCache` 重复布局 20 次取中位数；
  - **首屏**：100 段 ≈ 1 万字章节的完整构建（布局 + 分页），3 次取中位数。
- 阈值可通过环境变量覆盖（`BUDGET_PAGE_BUILD_MS` / `BUDGET_CACHE_HIT_MS` / `BUDGET_FIRST_PAINT_MS`），用于验证失败路径。
- 脚本行为：在 `packages/reader_core` 下跑 `flutter test test/bench/budget_test.dart -r expanded`；解析 `BUDGET …pass=true` 行；重写 `性能基线.md`；测试失败或解析不到结果时退出码 1/2。
- 默认 `flutter test` 会跳过预算用例（需 `BUDGET_RUN=1`，由脚本设置），避免与其它测试并发争抢 CPU 导致计时抖动；CI 新增「性能预算检查」步骤运行 `dart tool/bench/budget_check.dart`，超预算时非 0 退出即失败。

| 指标 | 预算 | 实测 | 结果 |
|---|---:|---:|:---:|
| 单页构建（20 段） | <8ms | 5.3～6.4ms | 通过 |
| 缓存命中 | <4ms | 0.007ms | 通过 |


## 4. 验收对照

| 验收项 | 结果 |
|---|---|
| 单页构建 <8ms / 缓存命中 <4ms / 首屏 <1s 写成可执行检查 | 通过（`budget_test.dart` + `budget_check.dart`） |
| 超预算时脚本退出码非 0 | 通过（实测退出码 1；解析失败退出码 2） |
| 结果写入性能基线文档 | 通过（`方案/验收记录/性能基线.md` 由脚本生成，含时间/环境/预算/实测/结论） |

## 5. 已知限制

- 预算测试在 CI 共享 runner 上会受机器负载影响；当前 5.3ms 对 8ms 有约 34% 余量，若 CI 抖动导致偶发失败，先用环境变量放宽或用中位数更多次采样。
- 「首屏 <1s」按普通章节（1 万字）定义；148MB 的诸神愚戏 `openEpub` 本身约 1.06s（见 P2-26 §5.2），骨架在首帧出现，正文等待超过 1s，属大书解析成本，后续需异步解压/首章优先解析。
- 单页构建用合成文本（Ahem 字体），只衡量布局与分页成本，不含绘制；绘制帧预算属于渲染阶段（P2-29 之后）。

## 6. 执行方式

```bash
dart tool/bench/budget_check.dart                                  # 本地/CI 预算检查（写入基线文档）
BUDGET_PAGE_BUILD_MS=0.001 dart tool/bench/budget_check.dart       # 验证失败路径（退出码 1）
cd packages/reader_core && BUDGET_RUN=1 flutter test test/bench/budget_test.dart  # 单独跑预算断言
```

CI 配置 `.github/workflows/ci.yml` 在「各包分析与测试」之后追加：

```yaml
      - name: 性能预算检查
        run: dart tool/bench/budget_check.dart
```

`dart tool/bench/budget_test.dart` 默认在普通 `flutter test` 中 Skip，避免共享测试进程的并发负载放大计时（实测并发跑全套时单页构建会超过 8ms，独立进程 5.3～6.4ms）。
