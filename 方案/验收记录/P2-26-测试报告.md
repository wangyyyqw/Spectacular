# P2-26 测试报告：分页性能优化（S2 结论落地）

## 1. 实现

- `packages/reader_core/lib/layout/text_layout_cache.dart`：`TextLayoutCache`（LRU，默认 512 条）
  - 键 = 样式测量指纹 + 行宽 + `textScaleFactor` + leading 分布 + 行内 run 摘要 + 是否启用字形回调 + 文本；
  - `layout()` 命中直接复用 `TextLayoutResult`（同一对象），未命中才走 `TextLayoutEngine.layout`；
  - `hits/misses/hitRate/length` 统计，`clear()` 用于设置重排。
- `ComputedStyle.layoutFingerprint`：只含参与测量的字段（字号、行高、字距、词距、对齐、缩进、text-transform、white-space、字重、斜体、字体链、display、visibility），颜色/装饰/背景不进键。
- 移动端 `EpubChapterSource` 接线：
  - 段落测量改走 `_layoutCache.layout(...)`；
  - 章节目页结果缓存 `_pageCache[spineIndex]`，重复进入章节不再重排；
  - `applyOverrides`（P2-24 重排）同时清空段落缓存与分页缓存。
- 基准测试 `test/bench/pagination_bench_test.dart`：1 万字章节（100 段 × 100 字）冷分页 / 缓存复用 / 页命中耗时，打印 `BENCH ...` 行供 P2-28 预算脚本沿用。

## 2. 测试

```
cd packages/reader_core && flutter test
BENCH chapter_chars=10000 cold_ms=31.21 warm_ms=2.15 pages=21
BENCH page_hit_avg_us=1.24
00:32 +469: All tests passed!
```

`bash tool/run_all.sh` → 3 个包通过；`flutter analyze`、`dart format`、边界检查干净。

| 用例 | 断言 |
|---|---|
| 缓存命中 | 相同输入第二次返回同一结果对象；hits/misses 统计正确 |
| 键敏感度 | 宽度、字号、字距、行高、对齐、文本、行内 runs 变化都不命中 |
| LRU / clear | 超上限淘汰最久未用；clear 清条目与统计 |
| 正确性 | 缓存结果与直接布局的文本/行数/宽高一致 |
| 冷分页 | 1 万字章节 **约 20～31ms**（预算 <2s） |
| 缓存复用 | 预热后第二次分页 **约 1.5～2.2ms**，且全部命中（预热后 0 miss） |
| 翻页命中 | 页读取平均 **约 1.2～3.6µs**（预算 <4ms） |

## 3. 验收对照

| 验收项 | 结果 |
|---|---|
| 1 万字章节首次分页 <2s（中端机） | 本机桌面实测 20～31ms，远低于 2s；中端机真机未复测（见限制） |
| 翻页命中 <4ms | 页缓存读取平均 1.2～3.6µs；`PageCache`/`VirtualPager` 仍是既有 O(1) 命中路径 |
| 按 S2 结论选择逐段构建 | 通过（保留逐段 `TextLayoutResult`，缓存键覆盖 S2 要求的文本/字号/行高/字距/宽度/字体/语言相关项） |

## 4. 已知限制

- 中端机真机未复测；S2 的 macOS 桌面结论按「预算充足」沿用，P2-28 会把预算检查脚本化，真机数据后续补入性能基线文档。
- 缓存按 512 段上限（LRU），超长章节会淘汰；超大字号/极窄宽度下命中率不变，但首次分页仍线性于段落数。
- 页命中数据来自缓存读取本身，不含绘制；绘制耗时属于 P2-28/渲染帧预算范畴。
- 缓存不跨来源共享（每 `EpubChapterSource` 一份），多书切换各自维护，避免文本键冲突。
