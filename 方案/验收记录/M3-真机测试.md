### 问题 1 的排查与结论（已关闭）

**结论：不是产品缺陷，是验收脚本的坐标错误。**

排查过程：

1. 先用 widget test 模拟「外层 Scaffold（body=IndexedStack + NavigationBar）里放自带
   Scaffold 的书架页」，FAB 点击正常；再叠加真机 MediaQuery（1080×2400 / DPR 2.8125 /
   padding top 32 bottom 24）仍然正常 → 说明嵌套 Scaffold 与常用 insets 都不影响命中；
2. 在书架标题栏临时打印 FAB 的全局位置与 MediaQuery：
   `[diag] fab=233,676 sz=384x853 pad=41/0 ins=0`
   → FAB 左上角在逻辑坐标 (233,676)，换算物理为 (655,1901)，按钮底部约 y=2036；
3. 之前所有"无响应"的点击用的是 y≈1705（按截图目测），**落在按钮上方空白区**，
   所以既没有涟漪也没有 picker；
4. 用正确坐标 (830,1968) 点击 → 系统 `documentsui` 选择器立即弹出，导入成功。

修复动作：撤回验收阶段为规避"缺陷"而临时加的两个重复入口（标题栏「＋」、空态中央
按钮），恢复为只有右下 FAB 的原始设计；保留 `_import` 的 try/catch 与失败提示（选文件
异常不再静默）；新增 `test/home/nested_scaffold_fab_test.dart` 作为「HomeShell 嵌套
Scaffold 下书架 FAB 可点」的回归用例。
