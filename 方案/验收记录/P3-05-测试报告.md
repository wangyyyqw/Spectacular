# P3-05 测试报告：实现 IDPF/Adobe 字体解混淆

任务：支持两种混淆算法，解混淆产物落缓存目录，不改原书（P3 任务书 ｜ 预算 4h）

## 交付

- `packages/reader_core/lib/epub/font_obfuscation.dart`（P0-17 基础上扩展）
  - `FontEncryptionMap`：解析 `META-INF/encryption.xml`（EncryptedData → EncryptionMethod/@Algorithm + CipherReference/@URI），识别 IDPF/Adobe URI，未知算法记录；损坏 XML 返回空表
  - `DirectoryFontCache`：解混淆产物按 sha1(路径+长度) 键落盘（临时文件 + rename 原子写），命中不重复解密；任何 IO 失败退回直接计算
  - `FontObfuscator.adobeKey` **修正**：P0-17 用「UUID 去连字符 16 字节」，与通行实现（Readium 等）不符；按规范外遗留算法通行口径改为 SHA-1(identifier 原文 UTF-8)。IDPF 口径经 EPUB 3.2 OCF 规范核对无误（SHA-1 去空白 identifier、1040 字节、URI `http://www.idpf.org/2008/embedding`）
- `packages/reader_core/lib/epub/epub_document.dart`
  - openEpub 解析 encryption.xml 与 `META-INF/sinf.xml`（FairPlay 检测）
  - `EpubDocumentImpl.fontEncryption` + `readFontBytes(href, {cache})`：资源不存在返回 null；未混淆原样返回；混淆资源用 `package.meta.identifier`（OPF unique-identifier）解密；原书字节始终不动
- 码表：新增 `E_FAIRPLAY_ENCRYPTION`（informational，Reeden 120 号同口径——只检测不解密）；码表防漂移用例 44→45
- 测试：`test/epub/font_obfuscation_test.dart` 重写（10 用例：密钥口径、双算法往返、错误 identifier、FontLoader 排版、encryption.xml 解析、openEpub 集成 ×3、缓存命中）

## 验收对照

| 验收项 | 结果 |
|---|---|
| 2 个混淆样本解出可渲染字体 | ✅ 合成混淆 EPUB（IDPF + Adobe 各一）：openEpub → readFontBytes 解出字节与原字体完全一致，且 `FontCoverage.parse` 可解析（可渲染）；既有用例继续覆盖 FontLoader 加载后排版出墨 |
| 缓存命中不重复解密 | ✅ `DirectoryFontCache` 计数用例：同键第二次调用 compute 次数不变（读缓存文件） |
| 不改原书 | ✅ 解密后 ZIP 内原始条目仍为混淆态断言 |

## 关键实现决策

1. **Adobe 算法口径修正**：EPUB 3.2/3.3 规范只定义 IDPF 算法；Adobe 是规范外遗留（真实书籍在用），密钥取通行实现 = SHA-1(identifier 原文)、1024 字节。P0-17 的 UUID 字节密钥无法解开真实混淆书，属隐患修正。
2. **FairPlay 只检测不解密**（Reeden 120 号）：`sinf.xml` 存在即记 `E_FAIRPLAY_ENCRYPTION`（informational），不尝试解密。
3. **缓存键 = 路径 + 原始字节长度**：同书重开命中；不同书/换版不串。
