> 日期：2026-10-24　执行人：Lead　任务：P2-08（4h）
> 依赖：P2-07　参考：技术方案 §60.3（基线推进）、§60.7（首元素负 margin）、§60.8（可见 margin）；阅微 `ListExtKt.getAdjacentContainerBottom` / `ContainerDom.onLayout`

## 1. 实现

- `collapseMargins(first, second)`：CSS 2.2 折叠规则——正正取较大、负负取更负、正负相加。
- `BlockFlow.margin`：默认 `CssEdges.zero`；`TextFlowBlock` 取样式 `margin`；`TableFlowBlock` 透传内容盒的 margin；脱离流的盒（绝对定位、浮动）不参与折叠。
- `ColumnFlowBlock`：
  - 记录 `childTops`：各流内子块顶边相对内容区顶部的偏移；
  - 相邻子块间距 = `collapseMargins(前块 bottom, 后块 top)`，基线按「前块高 + 折叠间距」推进；
  - 首块上 margin 与末块下 margin **逸出**容器，并与容器自身 margin 再折叠一次（嵌套块逐层逸出）；
  - 内容高度 = 末块底边，不含逸出的首末 margin；
  - 剩余高度约束按「折叠间距 + 子块高」递减。
- `createFlowBox`：容器内容盒带上 `style.margin`，让整棵子树的 margin 参与折叠。

## 2. 与阅微的对照

阅微的做法（静态分析）：

- `ListExtKt.getAdjacentContainerBottom(children, i)`：从当前索引向前找最近的**非浮动** `ContainerDom`/`TableDom`，返回它的 `margin.bottom`。
- `ContainerDom.onLayout` 用相邻块底边算 `offsetTop`：
  - 无前块：`offsetTop = min(marginTop, 0)`（首块正 margin 被吃掉，交给父级）；
  - 前块 `bottom < 0`：取「更负」的那个；
  - 前块 `bottom >= 0`：`offsetTop = -min(prevBottom, marginTop)`，即正 margin 折叠成较大值；
  - `offsetBottom = min(marginBottom, 0)`；
  - body 首元素负 margin 有专门钳制 `shouldClampBodyFirstElementNegativeTopMargin`（§60.7，留给 P2-09）。
- `onMeasure` 推进 `height + offsetTop + offsetBottom`；`TableDom` 单独处理 top/bottom margin 与 offsetY。

我们采纳与不同的部分：

| 维度 | 阅微 | 我们 |
|---|---|---|
| 折叠实现 | `offsetTop/offsetBottom` 预偏移 + 相邻块 bottom 查找 | `collapseMargins` 显式实现 CSS 三态规则 |
| 首末 margin | 首块正 margin 直接不计；末块靠 `offsetBottom` | 首末 margin 逸出容器并与容器 margin 再折叠（更接近 CSS 嵌套折叠） |
| 正负混合 | 负值优先，丢掉正 margin | 正负相加（CSS 2.2） |
| 表格 margin | 单独分支处理 top/bottom | 透传内容盒 margin，按普通块折叠 |
| 首元素负 margin 钳制 | 有 | 留 P2-09 |
| 数据精度 | dp/px 打包成 int 再解包 | 全程 double |

- 只有 margin，还没有 padding/border：真实 CSS 中容器有 padding/border 时首末子块 margin 不应逸出，当前一律逸出。
