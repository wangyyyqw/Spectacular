# 阅微注释锚点处理分析

> 日期：2026-10-23　分析对象：阅微 2.3.2 静态分析资料
> 目的：弄清阅微如何把 EPUB 正文中的注释引用解析到注释目标，再决定我们的锚点策略。

## 1. 阅微的做法

### 1.1 导入期改写 DOM

`org/epub/structure/HtmlOptimizer.java` 的 `optimizeA`（约 256 行起）在导入时扫描所有 `<a>`：

1. 先收集所有 `href` 中 `#` 前的目标文档；**不同目标文档超过 5 个就直接 return**，整章注释不做处理。
2. 跳过导航文档（`nav.xhtml` / `nav.html` / `toc.ncx`）。
3. 对每个带 fragment 的链接，按当前文件目录解析目标文档（`path.parent.resolve(dir)`）。
4. 在目标文档里 `getElementById(fragment)`；找不到就跳过。
5. 用 `getNodeAnnotation` 找“注释容器”，把注释文字写进引用元素的 `title` 属性；同时比较引用与目标的 CFI，目标在引用之后时把注释容器设成 `role="none"` 隐藏，并记录回链 `a[href]`。

### 1.2 注释容器定位

`resolveFootnoteItemContainer`（约 510 行）按顺序尝试：

- **回链优先**：在目标元素内找 `a[href="#源id"]`，从该回链向上找最近的 `li` / `p` / `aside` / `.duokan-footnote-item`。
- **单列表项**：目标是 `ol`/`ul` 且只有一个 `li`，直接用该 `li`。
- **序号前缀匹配**：遍历 `li`，用引用文字生成候选前缀（`1`、`(1)`、`（1）`、`1)`、`1）`），匹配 `li` 文本开头。
- 找不到则退回 `nearestFootnoteItemContainer`（从目标向上找 `li`/`p`/`aside`/`.duokan-footnote-item`）。

`candidatePrefixes`（约 586 行）会剥掉半角/全角括号，再组合出四种候选。

### 1.3 阅读期展示

- `ContentDom` 读取 `data-wr-footernote`（`Attr.java:19`）或 `title`，经 `normalizeComment` 规范化后渲染成气泡/注解。
- `CommentTooltipKt` 负责浮层与返回位置；`CommentAnnotation` 是阅读期注释模型。
- 静态分析资料中**没有找到写入 `data-wr-footernote` 的代码**（技术方案 §25.2 已记录），只能确认读取端；`title` 是导入期实际写入的字段。

### 1.4 已知问题

| 问题 | 说明 |
|---|---|
| 依赖导入期改写 | 改写失败/未覆盖的链接就没有注释，原书被永久修改 |
| 5 个目标文档上限 | 链接目标超过 5 个文档时整章放弃，真实书很容易触发 |
| 容器隐藏 | 注释容器被设 `role=none`，原 DOM 结构被改，后续定位与无障碍都受影响 |
| 回链缺失 | 没有回链时只能靠序号前缀，匹配失败就没有注释 |
| 资料缺口 | 写入 `data-wr-footernote` 的代码未恢复，无法确认完整字段 |

## 2. 我们的策略

不改写原书，在解析期生成锚点；保留“阅微式”回退，但把失败显式化。

`packages/reader_core/lib/epub/footnote.dart`：

- `FootnoteParser.parse`：解析单章 XHTML，建立 id 表，收集 `a[href*="#"]` 候选，初步识别 `noteref` / `footnote` / `endnote` / 普通链接。
- `FootnoteParser.resolve`：在文档集合中按顺序解析目标：
  1. 精确 id；
  2. 大小写不敏感 id；
  3. 回链锚点（目标内有 `a[href="#源id"]`）；
  4. 注释序号前缀（仅 `li` 或带 footnote class 的 `p`，避免把正文段落误判）；
  5. 失败 → `targetSpine` 保留目标章、`targetId=null`、`strategy=unresolved`，不隐藏原文。
- 注释文字取最近容器（`aside`/`li`/`p`/footnote class），剥掉序号前缀，截断 500 字。
- `EpubDocumentImpl.parseFootnotes(spineIndex)` 从 ZIP 读章节并解析，可直接接入后续文档树。

### 2.1 与阅微的差异

| 维度 | 阅微 | 我们 |
|---|---|---|
| 原书 | 导入期改写 + 隐藏容器 | 只读解析，不改 DOM |
| 目标上限 | 超过 5 个目标文档放弃 | 不设全局上限，按文档集合解析 |
| 失败 | 静默无注释 | `AnchorStrategy.unresolved` + 保留目标章 |
| 回退 | 回链、单 li、序号前缀 | 精确 id、大小写、回链、序号前缀（限定 li/footnote p） |
| 去重 | 按 href 去重 | 保留每条锚点，由调用方按需去重 |
| 展示 | `title` / `data-wr-footernote` 气泡 | 暂只产出锚点，展示在文本层实现 |
