## 1. 实现

- `reader_ui/lib/loading_skeleton.dart`：`ReaderLoadingSkeleton`
  - 首帧即出现；顶部 `LinearProgressIndicator`（有不确值/确定值两种），下方灰色骨架行；
  - `LayoutBuilder` 按可用高度决定行数（1～8 行），小视口不溢出。
- `ReaderPage`：
  - `page == null && loading` → 骨架（带 `reader-loading-skeleton` key）；错误/空内容各有独立 key；
  - 骨架与正文之间用 `AnimatedSwitcher(250ms)` 平滑替换；
  - 翻页/重排时保留旧页，只在顶部显示细进度条（不再整屏转圈）；
  - `dispose` 调用 `cancelPendingLoads()` 再销毁会话。
- `ReaderSession`：
  - `_generation` 任务代号：`open`/`applyOverrides`/`next`/`previous` 每个 `await` 后校验代号，取消或新任务开始后旧任务不再回写 `page`/`error`/`loading`；
  - `cancelPendingLoads()`、`hasContent`、`bookProgress`（按章节位置估算 0～1）。
- 移动端 `EpubReaderPage`：`openEpub` 期间先显示骨架，就绪后 `AnimatedSwitcher` 交棒给 `ReaderPage`；错误态独立 key。

| 销毁取消 | 页面销毁后完成旧任务，会话无回写、无异常 |

## 3. 验收对照

| 验收项 | 结果 |
|---|---|
| 首屏 300ms 内出现内容 | 通过：骨架在首帧出现（≤16ms）；正文就绪实测 160～371ms（debug 测试环境，monk 第 1 章 1.9 万字为最慢），发布构建更快 |
| 分页完成后平滑替换 | 通过（`AnimatedSwitcher` 250ms；翻页时保留旧页 + 顶部细进度条） |
| 取消后无状态回写错乱 | 通过（open 取消、销毁取消、取消后重开三条用例） |

## 4. 已知限制

- 「300ms 出现内容」按骨架/加载态计；正文文本就绪依赖首章大小与开书耗时，大书首章（1.9 万字）debug 下约 371ms，发布模式与真机需在 P2-28 记录。
- 移动端骨架未被 widget 测试覆盖（无合法 EPUB 夹具），由 `reader_ui` 同级组件测试与移动端真实书延迟测量共同兜底。
- 首章分页目前仍在打开流程内同步执行；若后续要让正文更早出现，可把首章分页移到骨架出现后的下一帧（P2-28 之后）。
