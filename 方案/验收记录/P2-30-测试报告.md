# P2-30 测试报告：段落缓存生命周期

> 日期：2026-10-24　执行人：Lead　任务：P2-30（3h）
> 依赖：P2-26　参考：技术方案 §64.6（缓存生命周期）、`ui.Paragraph` 释放语义；阅微按样式指纹缓存 Paragraph、重排整体失效的做法

## 1. 实现

- `packages/reader_core/lib/paint/paragraph_cache.dart`：`ParagraphCache`
  - 键：页号 + 切片序号 + 行号 + 字号的字号/行高/字距/词距/颜色 + justify 余量（由绘制侧组装，保证同一页同一布局命中）；
  - `obtain(key, build)`：命中复用同一 `TextPainter`，未命中构建后写入；
  - LRU 上限（默认 256），驱逐时调用 `TextPainter.dispose()` 释放底层 `ui.Paragraph`；
  - `bindLayout(fingerprint)`：布局指纹变化时清空并释放全部旧段落（重排后旧缓存全部失效）；同指纹重复绑定不清理；
  - `clear()/dispose()`：释放全部段落并重置命中统计。
- 绘制接线（`page_renderer.dart`）：
  - `PagePainter` 增加可选 `paragraphCache`；文本、装饰（着重号）、选区三个需要行排版的地方统一走 `_linePainterFor`，命中缓存时不再每帧重建 `TextPainter`；
  - 未传缓存时行为与之前完全一致（每行新建），既有像素测试不受影响。
- UI 接线（`reader_page.dart`）：
  - 默认自建 `ParagraphCache(maxEntries: 256)`，可选传入（便于测试/共享）；
  - 设置变化（`overrides` 改变）时先 `clear()` 再触发重排；主题变化不清空；
  - 页面销毁时自建缓存 `dispose()`。

## 4. 已知限制

- 缓存以「页 + 行」为粒度，缓存按键含颜色，主题换色会产生新键、旧键按 LRU 自然淘汰（不视为泄漏）。
- 跨页/翻页后旧页条目依赖 LRU 淘汰，不做按页显式驱逐；若后续发现翻页抖动可加 `evictPage(spineIndex, pageIndex)`。
- 行内上下标分段绘制时仍会为每段新建 `TextPainter`（段级缓存收益有限，未做）。
- `ReaderPage` 只在自己创建缓存时负责 `dispose`；传入缓存的生命周期由调用方管理。
