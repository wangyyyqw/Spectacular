# 性能采集说明

> 任务：P0-22（依赖 P0-14）。适用于 P0 之后的每次性能相关变更；目标是让“优化前后”可对比。

## 1. 采集原则

- 同一设备、同一构建模式、同一字体与字号，一次只改一个变量。
- 每组采样至少 3 次，取中位数；异常值（首次编译、后台任务）单独标注。
- 记录 Flutter/Dart 版本、设备型号、系统版本、屏幕 DPR、构建命令。
- 数据落 `方案/验收记录/性能-<主题>.md`，不写“感觉更快”。

## 2. 三类采集

### 2.1 测量/分页（JIT 基线）

```bash
bash tool/bench/run_bench.sh
```

记录：字数、段落数、页数、冷总耗时、单页均摊、缓存复用耗时。适用于算法级对比，不代表真机体验。

### 2.2 真机帧与耗时（profile）

```bash
cd apps/reader_mobile
flutter run --profile -d <device-id>
```

- 打开 DevTools → Performance，录制“冷启动 → 打开书 → 连续翻 30 页”。
- 记录：首屏时间、最长帧、掉帧数、分页完成时间、内存峰值。
- 同时抓 `flutter screenshot` 或系统录屏作为附件（放 `方案/验收记录/attachments/`，不入库大文件）。

### 2.3 内存与缓存

- DevTools Memory：打开书前后、连续翻 50 页、切换主题后的堆快照。
- 记录：图片缓存数、段落缓存命中率、字体缓存字节数、峰值内存。
- 判定线参考技术方案 §11.2 与 §44.4；超出预算先定位再优化。
