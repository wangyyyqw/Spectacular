# P7-29 缓存键检查清单

> 任务：P7-29 ｜ 日期：2026-10-24
> 原则（对照 Reeden 660 号键设计检查清单）：**缓存键必须包含「影响该层的最小变量集」**——漏键必然撞键返回旧值，多键则无谓失效。
> 结论：审计发现并修复 1 处真实漏键（P7-18~21 新增排版输入不在 `layoutFingerprint`）；全部既有键过检。

## 1. 过检清单（新增任何排版输入时逐条回答）

1. **影响哪层**：document（文本对象）/ styles（样式派生）/ pagination（分页决策）/ 段落布局 / 绘制？
2. **键里有没有它**：该层的缓存键字段是否包含此输入（含间接来源——如 `layoutFingerprint` 聚合键）？
3. **失效怎么传**：输入变化时能否沿层传播（styles 变 → pagination 键变 → 页重建）？
4. **主题是否排除**：纯绘制输入（颜色/背景）必须**不**进排版键（零重排）；
5. **增量是否可能**：能否按 section/章粒度续排而非整包失效？

## 2. 既有缓存键审计（技术方案 §11.1 全表）

| 缓存 | 键组成（实测代码） | 审计结论 |
|---|---|---|
| 段落布局 `TextLayoutCache` | `layoutFingerprint + maxWidth + textScaleFactor + leadingDistribution + hasGlyph + runs(区间/偏移/指纹) + text` | **发现漏键已修**：指纹缺 P7-18~21 五输入（hanging/textSpacingTrim/autospace/textJustify/textAlignLast/initialLetter）——它们影响缓存内的 justifyExtra 与行宽，会撞键返回旧宽度。已扩展指纹（computed_style.dart）并加 5 指纹互异 + 缓存不撞键测试 |
| 页缓存 `_pageCache`（P7-23） | `spineIndex@宽x高\|overrides.fingerprint` | ✅ 几何+排版字段；颜色不进键（零重排） |
| 页索引 `_pageIndexCache`（P7-22/23） | 同页缓存键 + 文件内 schemaVersion + 累加和 | ✅ schema 换代即失效 |
| document `_documentCache`（P7-23） | `spineIndex` | ✅ white-space 每实例恒定；内容变化（一期无）走整源重建 |
| 页渲染缓存 `ParagraphCache`（P2-30） | 布局指纹（bindLayout 显式传入） | ✅ 指纹变化全失效有测试；随 layoutFingerprint 修复自动获得新字段 |
| 页缓存 `PageCache`（reader_ui，P1-29） | 页序号 + loader 身份；失效由上层 fingerprint 驱动（P2-24 链路） | ✅ |
| 图片缓存 `ImageCache` | (href, 显示宽, DPR) | ✅ §11.1 口径 |
| UA 覆盖层 `uaStyles` 按章 map | tag → 覆盖样式（loadChapter 内局部） | ✅ 每章重建，无跨设置存活 |
| CSS 规则表（§11.1：内容 hash，2048 条） | 未实现（P4 随作者样式接入） | 登记 P4-01 设计时按本清单过检 |
| 字体缓存（§11.1：family+字重全局） | 未实现（P3-02） | 登记 P3-02 过检（family→(weight,italic) 二元组，P7-08 已验证） |

## 3. 本轮修复的证据

- `layoutFingerprint` 扩展前后 5 组样式指纹互异（`text_layout_cache_test` ▸ P7-29 键完整性）；
- trim/autospace/justifyAll/hanging 与 base 互不撞键（缓存 misses ≥ 5）；
- 既有键行为不回退（全套 600 例通过）。
