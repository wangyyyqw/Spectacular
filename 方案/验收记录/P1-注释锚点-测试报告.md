## 3. 覆盖

| 场景 | 结果 |
|---|---|
| `<a epub:type="noteref" href="#fn1">` + `<aside id="fn1">` | 精确命中，注释文字提取正确 |
| `<sup><a href="#n1">[2]</a></sup>` + `<p id="n1">` | 识别为 footnote，目标正确 |
| `class="duokan-footnote"` + `.duokan-footnote-item` | 识别并提取容器文字 |
| 目标 id 缺失，列表项以 `4 ` 开头 | `textPrefix` 命中，`targetId` 可空 |
| 目标 id 缺失，目标内有回链 `#r2` | `backlink` 命中，定位到带 id 的容器 |
| `href="ch2.xhtml#fn1"` 跨文档 | `targetSpine=1`，`crossDocument=true` |
| 普通章节链接 `#sec1` | `NoteKind.link`，不误判 |
| 目标不存在 | `strategy=unresolved`，保留目标章，`noteText=null` |
| 内存 EPUB 全链（打开 → 解析 → 跨章 resolve） | 通过 |

## 4. 已知限制

- 单章 parse 不递归解析目标文档；跨文档需要调用方把相关章解析后传入 `resolve`。
- 序号前缀匹配只覆盖 `li` 与带 footnote class 的 `p`；更复杂的注文结构依赖后续文档树。
- 不处理 `pageList` 中的注释；不解析 `data-wr-footernote`（阅微专有字段）。
- 未接入阅读期气泡/返回位置，展示层在文本层任务实现。
