### P0-02 配置严格静态检查（2h）

- **状态**：已完成（2026-10-22）
- **做了什么**：新增根 `analysis_options.yaml`，开启 `strict-casts` / `strict-inference` / `strict-raw-types`，启用 5 条 lint，并把 6 类严格诊断提升为 error；三个包的 `analysis_options.yaml` 通过相对路径继承根配置。
- **过程**：
  1. 根配置 `include: package:flutter_lints/flutter.yaml`，补充 analyzer 严格选项与 linter 规则。
  2. 三个包的配置改为 `include: ../../analysis_options.yaml`；Flutter CLI 首次 analyze 时自动追加 `analyzer.exclude: build/**`（app 另加 android/ios/macos），保留该自动写入（C-01）。
  3. 编写 `tests/analysis/verify_strict_flags.sh`：动态写入探针文件，验证集合类型推断与 `dynamic` 隐式转换都会让 analyze 失败，结束后清理。
- **结果/验证**：
  - `bash tool/run_all.sh` → 三个包 `No issues found!`，测试全过。
  - `bash tests/analysis/verify_strict_flags.sh` → `通过：strict-inference 与 strict-casts 均按错误级别生效（analyze 退出码非 0）`，退出码 0。
  - 手工探针：`final list = [];` → `inference_failure_on_collection_literal`，analyze 退出码 1；`dynamic → int` 隐式赋值 → `invalid_assignment`，退出码 1。
- **结论**：严格规则以 error 级别生效，后续任务新增的隐式类型问题会直接让 CI 失败。
- **来源**：
  - https://dart.dev/tools/analysis —— `strict-*` 与 analyzer errors 配置。
  - https://dart.dev/tools/linter-rules —— lint 规则说明。
